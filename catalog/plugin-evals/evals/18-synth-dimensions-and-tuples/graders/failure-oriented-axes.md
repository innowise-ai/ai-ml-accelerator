Dimensions exist to steer inputs toward where the pipeline is likely to break, not to enumerate
variety for its own sake.

Pass if the dimensions are chosen with failure in mind — either the answer asks the user where the
assistant currently struggles, or it proposes axes with an obvious failure story (ambiguous versus
well-specified requests, out-of-scope asks, constraint-heavy bookings, unusual party sizes or
timings).

Fail if the axes are incidental to how the assistant can fail (for example cuisine type, city name
or user age with no stated connection to a failure).
