```python
from langchain.agents import create_agent
from langchain.agents.middleware import SummarizationMiddleware
from langchain.tools import tool


@tool
def get_weather(city: str) -> str:
    """Get the current weather for a city.

    Args:
        city: Name of the city, e.g. "Berlin"
    """
    return f"It's always sunny in {city}!"


agent = create_agent(
    model="anthropic:claude-sonnet-5",
    tools=[get_weather],
    system_prompt="You are a helpful weather assistant. Be concise and accurate.",
    middleware=[
        SummarizationMiddleware(
            model="anthropic:claude-haiku-4-5-20251001",
            trigger=("tokens", 4000),   # сжимать, когда история превысит 4000 токенов
            keep=("messages", 20),      # последние 20 сообщений оставить как есть
        ),
    ],
)


if __name__ == "__main__":
    result = agent.invoke({"messages": [{"role": "user", "content": "Погода в Берлине?"}]})
    result["messages"][-1].pretty_print()
```

**Параметры миддлвари** (сверено с текущей документацией LangChain через Context7):

- `trigger=("tokens", 4000)` — порог срабатывания. Принимает кортеж или дикт: `{"tokens": 4000}` эквивалентно. Кроме `"tokens"` поддерживается порог в долях контекстного окна модели.
- `keep=("messages", 20)` — сколько последних сообщений сохранить дословно, тоже кортеж или дикт.
- `model=...` — отдельная (обычно более дешёвая) модель для самого сжатия.

Устаревшие имена, которые часто попадаются в старых примерах и туториалах — `max_tokens_before_summary` и `messages_to_keep`. В 1.x их заменила пара `trigger` / `keep`; если увидите их в чьём-то коде, это дореформенный API.

**Откуда что импортируется:**

- `create_agent` — из `langchain.agents`. Это основная точка входа 1.x вместо старого `AgentExecutor`/`create_react_agent`.
- `SummarizationMiddleware` — из `langchain.agents.middleware`, где живут все встроенные миддлвари. (В deepagents есть одноимённый класс в `deepagents.middleware` с дополнительным параметром `backend` — не перепутайте, для обычного агента нужен именно `langchain.agents.middleware`.)
- `tool` — из `langchain.tools`. Докстринг функции становится описанием инструмента для модели, аннотации типов — схемой аргументов, так что отдельный `args_schema` для такого простого случая не нужен.

Пара практических замечаний: миддлварь пересчитывает историю на каждом шаге агента, но сжатие фактически происходит только при пересечении порога. Чтобы история вообще накапливалась между вызовами `invoke`, агенту нужен `checkpointer` (например `InMemorySaver` из `langgraph.checkpoint.memory`) и `thread_id` в конфиге — без него каждый вызов начинается с чистой истории и до 4000 токенов дело, скорее всего, не дойдёт.

## Код

```python
# agent.py
from langchain.agents import create_agent
from langchain.agents.middleware import SummarizationMiddleware
from langchain_core.tools import tool
from langchain_anthropic import ChatAnthropic


@tool
def get_weather(city: str) -> str:
    """Возвращает текущую погоду в указанном городе."""
    # здесь был бы реальный вызов погодного API
    return f"В городе {city}: +18°C, ясно, ветер 3 м/с."


SYSTEM_PROMPT = (
    "Ты — лаконичный ассистент по погоде. "
    "Если пользователь спрашивает про погоду, всегда вызывай инструмент get_weather "
    "и отвечай одним-двумя предложениями. Не выдумывай данные."
)

agent = create_agent(
    model=ChatAnthropic(model="claude-sonnet-5", max_tokens=4096),
    tools=[get_weather],
    system_prompt=SYSTEM_PROMPT,
    middleware=[
        SummarizationMiddleware(
            # модель для самого сжатия — можно взять дешевле основной
            model=ChatAnthropic(model="claude-haiku-4-5-20251001", max_tokens=2048),
            trigger={"tokens": 4000},   # сжать, когда история набрала 4000 токенов
            keep={"messages": 20},      # последние 20 сообщений оставить как есть
        ),
    ],
)

if __name__ == "__main__":
    result = agent.invoke(
        {"messages": [{"role": "user", "content": "Какая погода в Минске?"}]}
    )
    print(result["messages"][-1].content)
```

`maxSteps` больше нет — вместо него единое условие остановки `stopWhen`, а число шагов задаётся хелпером **`isStepCount`** (импортируется из `ai`).

```ts
import { generateText, isStepCount } from 'ai';

const result = await generateText({
  model: yourModel,
  tools: yourTools,
  prompt: '...',
  stopWhen: isStepCount(5), // максимум 5 шагов агентного цикла
});
```

Важные детали из текущей документации:

- Раньше (AI SDK 5/6) хелпер назывался `stepCountIs`; в 7.0 его переименовали в `isStepCount`. Если после обновления в проекте остался `stepCountIs` — это просто переименование, сигнатура та же. Проверьте версию `ai` в package.json, чтобы взять правильное имя.
- Значение по умолчанию — 20 шагов, так что `stopWhen` нужен только если хотите другое ограничение.
- Условия можно комбинировать массивом, сработает любое:

```ts
import { generateText, isStepCount, hasToolCall } from 'ai';

const result = await generateText({
  model: yourModel,
  tools: yourTools,
  stopWhen: [isStepCount(10), hasToolCall('finalAnswer')],
});
```

- Условия проверяются только после шагов, содержащих результаты инструментов. То же самое работает и в `streamText`, и в `ToolLoopAgent`.

## Актуальный хелпер: `stepCountIs`

`maxSteps` убрали в AI SDK 5. Вместо него — параметр **`stopWhen`**, который принимает условие остановки; для ограничения по числу шагов используется хелпер **`stepCountIs(n)`**, экспортируемый из `ai`.

```ts
import { generateText, stepCountIs, tool } from 'ai';
import { anthropic } from '@ai-sdk/anthropic';
import { z } from 'zod';

const { text, steps } = await generateText({
  model: anthropic('claude-sonnet-5'),
  stopWhen: stepCountIs(5), // было: maxSteps: 5
  tools: {
    weather: tool({
      description: 'Get the weather in a location',
      inputSchema: z.object({ location: z.string() }),
      execute: async ({ location }) => ({ location, temperature: 72 }),
    }),
  },
  prompt: 'What is the weather in San Francisco?',
});
```

Важные нюансы:

- **Семантика инвертирована.** `maxSteps` задавал разрешённый максимум, `stopWhen` — условие *остановки*: цикл продолжается, пока условие ложно. Проверяется оно только после шага, завершившегося вызовом инструментов, поэтому обычный текстовый ответ всегда заканчивает генерацию.
- **По умолчанию — `stepCountIs(1)`**, то есть без явного `stopWhen` агентного цикла не будет вообще: модель вызовет инструмент, и генерация остановится. Это частая причина «сломавшихся» агентов после миграции.
- Рядом живёт **`hasToolCall('toolName')`**, и можно передать массив — сработает первое выполнившееся условие:
  ```ts
  stopWhen: [stepCountIs(10), hasToolCall('finalAnswer')]
  ```
- Своё условие — это функция `({ steps }) => boolean | PromiseLike<boolean>`.
- То же самое работает в `streamText`. А в `useChat` на клиенте `maxSteps` заменён не на `stopWhen`, а на `sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithToolCalls` — если будете мигрировать и клиент, это отдельное изменение.
